## 1. Elaborated Acceptance Criteria (Ready Items)

The following acceptance criteria are established only for delivery items classified as **Ready**. They are written declaratively to avoid inventing UI, technical design, or unconfirmed validation rules.

### US-01: Create Planned-Maintenance Notice
* **Upstream Requirement:** REQ-001 (Confirmed)
* **Acceptance Criteria:**
  * **AC-01.1 (Notice Creation):** A Service Desk Analyst can create a planned-maintenance notice record.
  * **AC-01.2 (Required Attributes):** The notice record supports the following attributes:
    * Affected service
    * Maintenance-window start (date/time)
    * Maintenance-window end (date/time)
    * Impact summary

### US-02: Reference Approved Change ID
* **Upstream Requirement:** REQ-002, REQ-011 (Confirmed)
* **Acceptance Criteria:**
  * **AC-02.1 (Approved Change Reference):** A planned-maintenance notice must reference an approved Change ID before the notice can be published.
  * **AC-02.2 (Process Preservation):** The referencing mechanism must not alter the existing Change approval process or existing approval authorities.

### EN-01: Retain Publication Outcome
* **Upstream Requirement:** REQ-003 (Confirmed)
* **Acceptance Criteria:**
  * **AC-03.1 (Outcome Logging):** The notice record retains the outcome of the publication attempt.
  * **AC-03.2 (Timestamp Logging):** The notice record retains the date and time associated with the publication outcome.

### US-03: Manual Publication Fallback
* **Upstream Requirement:** REQ-012 (Confirmed)
* **Acceptance Criteria:**
  * **AC-04.1 (Manual Fallback):** Manual publication of a planned-maintenance notice remains available to users when the notification-platform integration is unavailable.

### EN-02: Integration Security Constraints
* **Upstream Requirement:** REQ-010 (Confirmed)
* **Acceptance Criteria:**
  * *Note: These criteria apply as mandatory constraints if and when any notification integration work proceeds.*
  * **AC-05.1 (Service Identity):** The integration must reuse an approved service identity.
  * **AC-05.2 (Least Privilege):** The integration must apply the principle of least privilege.
  * **AC-05.3 (No Shared Admin):** The integration must not introduce a new shared administrator account.
