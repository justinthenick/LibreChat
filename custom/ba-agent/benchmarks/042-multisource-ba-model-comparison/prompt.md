Prepare a complete, implementation-ready Business Analysis package from the supplied source pack.

Use the supplied evidence only. Preserve source distinctions, contradictions, unresolved conditions and source strength. Do not decide an unresolved business rule merely because one interpretation appears obvious. Do not invent benefits, decision owners, governance bodies, implementation mechanisms, engineering gaps or non-functional requirements.

Produce, in one response:
1. Source register.
2. Requirements register with stable IDs and evidence/status classification.
3. Solution-neutral delivery backlog/decomposition.
4. Acceptance criteria only where the source evidence supports a testable outcome.
5. Requirements Traceability Matrix linking source -> requirement -> backlog item -> acceptance criteria/status.
6. Source-created contradictions, ambiguities and unresolved decisions.
7. Completeness/readiness assessment distinguishing implementation-ready areas from source-created unresolved areas.

Where sources conflict, mark the affected requirement Disputed/Candidate/Unknown as appropriate rather than silently selecting one source. Where a source establishes a condition but no outcome, preserve `Required outcome: Unknown / Not established from supplied evidence`.
