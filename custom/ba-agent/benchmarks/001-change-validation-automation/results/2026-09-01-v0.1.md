# Benchmark 001 — Run Results (2026-09-01)

## Test setup

- Same Gemini model/settings for both runs.
- Run A: baseline prompt, no skill.
- Run B: same prompt and input, with `$analyze-requirements` v0.1.
- Diagnostic follow-up confirmed the skill was loaded and the model could accurately reproduce its evidence classes and default output sections.

## Run A — Baseline

**Score:** 78/100

### Strengths
- Strong factual coverage.
- Correctly preserved the advisory-vs-blocking stakeholder disagreement.
- Correctly treated the two-minute response target as technically unproven.
- Strong decision-oriented open questions.
- No serious hallucinations identified.

### Main weaknesses
- Weak formal source traceability.
- Tentative "top 10" scope was promoted toward a firm requirement.
- Approximate six-week target was treated too strongly as a constraint.
- Evidence classes were not attached to individual requirements.

## Run B — Skill v0.1

**Preliminary score:** ~52/100 after penalties.

### Strengths
- Preserved the major stakeholder contradiction.
- Produced generally usable structure and open questions.

### Regressions / failure modes
- Failed to produce the mandated source register.
- Failed to use the mandated requirements-register fields: evidence class, source reference and confidence.
- Hardened tentative source wording into mandatory requirements/constraints.
- Treated the "top 10" idea as committed MVP scope although the source says "should probably".
- Treated the ~6-week target as a strict target although the source says "would like" and "about six weeks".
- Treated candidate integrations as firmer than supported despite API feasibility being unverified.
- Invented an immutability requirement for stored evidence that was not present in the source.

## Diagnostic result

A separate diagnostic invocation of `$analyze-requirements` correctly returned all six evidence classes:

- Explicit
- Inferred
- Proposed
- Assumption
- Disputed
- Unknown

It also correctly returned the full expected default output structure.

**Conclusion:** the skill was loaded successfully. The Benchmark 001 regression was therefore an instruction-adherence problem, not a LibreChat skill-loading failure.

## Decision

Do not retain v0.1 as production-ready. Create v0.2 with stronger mandatory output requirements, explicit uncertainty-preservation examples, and a pre-response compliance check.
