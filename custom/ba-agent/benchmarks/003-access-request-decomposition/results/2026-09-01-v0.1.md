# Benchmark 003 Results — Initial Decomposition Experiment

Date: **2026-09-01**  
Model: **Gemini 3.5 Flash**  
Benchmark: **Application Access Request Delivery Decomposition**

## Scores

| Run | Raw score | Penalties | Final score |
|---|---:|---:|---:|
| No decomposition skill | 83 | -10 | **73/100** |
| `decompose-requirements` v0.1 | 87 | -40 | **47/100** |

## Baseline findings

Strengths:

- correctly preserved the privileged-access approval dispute;
- treated automated provisioning feasibility as discovery rather than committed implementation;
- kept named pilot applications conditional;
- preserved the four-business-hour item as a Target in the body;
- kept automatic deprovisioning Deferred;
- did not force all work into user stories.

Weaknesses:

- no useful capability/epic grouping;
- did not explicitly state overall `Partially Ready` readiness;
- invented `tamper-evident` audit logging and actor details not present in REQ-007;
- used `SLA` terminology for the four-hour Target in a heading.

## v0.1 skill findings

The skill materially improved the **raw decomposition method**:

- explicit `Partially Ready` assessment;
- full upstream status map;
- coherent capability grouping;
- mixed work-item types;
- REQ-004 became a Decision Item with `Decision owner: Unknown`;
- REQ-006 became a proper Spike;
- Candidate, Target and Deferred work were separated;
- traceability coverage was much stronger.

However, serious downstream invention caused the final score to regress:

1. REQ-007 became a `chronological, immutable audit log` even though immutability was not established.
2. Manual fulfillment invented a user-facing `queue` mechanism.
3. Unknown retention decision ownership was supplemented with unsupported `Security/Compliance governance` escalation.
4. Pilot-scope approval invented `Product Owner and Business Sponsor sign-off` authority.
5. Additional unsupported mechanisms appeared, including notification/approval screens, database archiving/purging, hard-coded application fields, technical documentation and sandbox environments.
6. Traceability referenced `TSK-002`, which did not exist.

## Decision

**Do not validate/retain v0.1 as production-quality.**

The decomposition framework is promising, but evidence discipline must extend downstream into backlog wording, dependencies, risks, decision ownership and cross-references.

Skill v0.2 should preserve the improved hierarchy while adding strict controls against unsupported downstream qualities/mechanisms, inferred decision authority and phantom work-item IDs.
