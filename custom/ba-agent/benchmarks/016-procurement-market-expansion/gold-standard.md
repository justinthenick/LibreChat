This file is evaluator-only and must not be sent to the model under test.

## Overall conclusion

The supplied history is **over-concentrated in three marketplace channels** (eBay, Facebook Marketplace and Gumtree), with repeated query variants and declining new-result yield. The correct next step is not another near-identical marketplace sweep.

A strong response should increase exploration materially above the Skill's default 20% because current source diversity and freshness are poor. A defensible plan would be approximately **50/50 exploit/explore or 40/60 exploit/explore** for the next pass. Exact percentages are not mandatory if the rationale is sound.

## Expected search-state interpretation

- eBay Australia: heavily exploited; repeated workstation/model searches; inventory appears repetitive/stale.
- Facebook Marketplace: heavily exploited across Central Coast/Sydney/Newcastle; many duplicates and weak seller evidence.
- Gumtree: repeatedly exploited; low new-result yield.
- Current source mix is marketplace-heavy rather than broad market coverage.
- Many URLs or queries inside the same marketplace do not count as genuinely different source classes.

## Expected exploration directions

A strong answer should add several genuinely new channel classes from the unsurveyed set, such as:

1. **Specialist business-PC/workstation refurbishers** with direct inventory rather than marketplace storefronts.
2. **Ex-lease / ITAD channels** where enterprise towers may be sold by configuration or asset batch.
3. **Government/corporate surplus, liquidation or auction channels**.
4. **Local computer recyclers/refurbishers** with direct stock and potentially inspectable exact units.
5. **Specialist workstation dealers**.
6. **Manufacturer/direct outlet or open-box channels**, where relevant.
7. **Interstate shipped Australian inventory** from the new source classes, not merely another Australia-wide eBay query.

The answer need not include every channel, but it should demonstrate real source-class expansion.

## Expected adjacent solution-class exploration

At least one plausible adjacent host class should be considered without relaxing hard constraints, for example:

- verified used gaming towers sold without a GPU;
- barebones/full-size ATX systems from non-marketplace channels;
- enterprise/workstation towers outside the repeatedly searched P330/Z4/Precision model names.

These are exploratory classes only. They still need later exact-unit verification for slot, clearance, PSU wattage and GPU-power connector.

## Appropriate exploitation actions

Some exploitation is still useful, but it should be targeted rather than repetitive. Examples:

- revisit the strongest known eBay/Z4 or marketplace watch candidates only if there is a price change, seller-supplied exact PSU/connector evidence, stock refresh or a materially different filter;
- preserve saved searches/watches rather than manually rerunning the same query every day;
- recheck known productive sources on a defined refresh interval rather than continuously.

## Stop / refresh logic

A strong plan should define when to stop the next pass, for example after:

- each selected new source class has been searched once with at least one appropriate query/filter;
- no new technically plausible host class/source is emerging;
- viable candidates are sufficient for a verification shortlist;
- further searches are producing only duplicates or unsupported seller claims.

Revisit exhausted channels only on a meaningful change signal such as new inventory, price movement, new evidence or elapsed refresh interval.

## Non-negotiable boundaries

- Do not invent actual current listings, stock, sellers, prices or availability.
- Do not claim an unsurveyed source has already been searched.
- Do not weaken tower/full-height/242 mm/PSU/connector constraints merely to widen discovery.
- Do not present adjacent solution classes as verified candidates.
- Do not equate a new keyword combination inside eBay/Facebook/Gumtree with a new market channel.
